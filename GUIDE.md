# Windows editor and developer guide

This app prepares continuous, color-corrected clips with aligned, cleaned dialogue for a human editor. It does not make the story edit, captions, music, branding or final client approval automatically.

[Project index](INDEX.md) · [Technical handoff](CODEX_HANDOFF.md) · [Dashboard source](index.html)

## 1. Get the app

Clone the repository using Git:

```bat
git clone https://github.com/Sam-gah/videoaudio.git
cd videoaudio
```

Alternatively, download and fully extract the repository ZIP. Work inside the extracted folder, not inside the ZIP preview. You can keep the app on the laptop or in a writable folder on Transcend. The app writes imports and exports inside its own folder, so choose a location with enough free space.

The clone contains code, the approved LUT and documentation. It does **not** contain camera videos, audio recordings, the six finished clips, or the owner's local catalog.

## 2. Set up Windows once

Install Python 3.10 or later with pip if it is missing. Check in Command Prompt:

```bat
py -3 --version
py -3 -m pip --version
```

If your installation uses `python` instead of `py`, use `python --version` and `python -m pip --version`. The launch scripts support either command.

With internet available, double-click **Setup_Windows.bat**. It installs numpy, scipy and imageio-ffmpeg into this app's vendor folder. The FFmpeg package supplies a Windows binary; you do not need to use the owner's Mac binary. Wait for the setup-complete message.

Double-click **Start_Windows.bat**. A terminal opens and prints the local URL, normally `http://127.0.0.1:8765`; your browser opens automatically. If another app is using that port, use the URL actually printed. Keep the terminal open while working. After setup, media preparation works offline.

On first launch the app creates an empty local client library. This is expected. Opening index.html on GitHub does not launch the app. Double-clicking index.html locally is viewing-only mode and needs the catalog generated by a previous launch.

This is a source application with launch scripts, not a packaged Windows .exe. Automated testing was done on Mac; validate one real clip on the Windows laptop before processing a batch.

## 3. Choose the media on Transcend

Connect the drive and check its drive letter in File Explorer. It may be `E:`, `F:` or something else; paths from the owner's Mac are not usable on Windows.

1. Use **Add client** and enter the actual client's name. Keep different clients separate, even if camera filenames repeat.
2. Open **Import folders**.
3. Use **Choose…** beside Camera video folder and select that client's camera originals. Choose the separate audio folder too. If the folder picker is unavailable, paste the full paths manually.
4. Use **Copy media into library** and wait for the preparation queue to finish.

For example, a camera folder may be under `E:\production bichitras\tru dent + hygenic clips + photos\vids`, and Trudent recordings under `E:\production bichitras\tru dent audio`. Confirm the actual folders and client ownership before importing; the mixed video folder can contain another client's footage.

Imports copy supported media and Sony XML sidecars; they do not move or alter originals. Do not select the entire drive. Do not mix every production folder into one client. If an import would overwrite an existing filename at the same relative path, it stops with an error rather than silently replacing it. Leave the drive connected during import, matching and rendering.

Local organization after import:

```text
projects/<client>/
  video/          copied camera originals
  audio/          separate recordings and new clean-dialogue WAVs
  final/          uniquely named prepared exports
  reports/        matching suggestions and local analysis cache
  project.json    review notes, source mapping and chosen settings
```

New export folders also contain PREPARATION.json. All project media, local state and installed dependencies are Git-ignored. Do not force-add them to the public repository.

## 4. Confirm one representative clip first

Before a batch, choose one short clip for each client, camera profile and lighting setup. Confirm the real camera profile, input range, orientation and recording identity. The previously approved LUT is a reference for **full-range S-Log3/S-Gamut3.Cine** and includes Trudent's exposure and white-balance choices. It is not a guarantee of natural skin under different lighting.

### Match and check dialogue

Select a camera video under **Video**, then use **Find audio candidates**. Suggestions compare camera scratch audio with this client's separate recordings. A high score does not approve a match. Listen to the recording and camera clip, then check lips or distinctive transients at the start, middle and end.

When choosing a candidate, the app enters an approximate offset and overlapping camera range. Convention:

```text
audio time = camera time + offset
```

A positive offset means the selected dialogue begins later in the recording. A negative offset means the recording began after the camera. Refine the offset if needed, then keep the camera in/out range inside the actual audio coverage.

The matcher analyzes at most the first 30 minutes of a recording; split longer recordings before matching. No usable camera scratch audio means an automatic match may be impossible. Do not guess a recording based on its filename or stretch incomplete audio to fill a shot.

If a separate recording cannot be confirmed, hold the clip or explicitly select **Use camera audio instead (fallback)**. That choice is flagged. It is not equivalent to verified separately recorded dialogue.

### Preview the picture

Choose the input color profile explicitly:

- **S-Log3 / S-Gamut3.Cine: approved Trudent look** only when that profile and full-range input are confirmed.
- **Already Rec.709: no LUT** for footage that is already correctly converted.
- Leave **Not confirmed** selected when unsure; processing will require a valid choice.

Choose rotation separately. New clips do not automatically inherit the test batch's portrait orientation. Save settings, use **Grade preview**, and inspect natural skin, exposure, highlights and framing. If the preset is unsuitable, do not approve a batch: have the developer/editor adjust the scene-specific grade first.

## 5. Prepare and hand off

Use **Prepare 1080p** after checking the settings. Jobs run one at a time. Identical pending requests are deduplicated, and queued renders preserve the settings saved when submitted.

The app creates a new H.264 export, with the original aspect ratio and maximum 1920 pixels on the long side, plus a 48 kHz/24-bit cleaned dialogue WAV. It applies conservative audio filtering/compression, loudness normalization and denoiser timing compensation. It does not automatically create a new 4K master or overwrite previous exports. Full-stream decoding checks for encoding errors; this is not a human sync or quality approval.

Find the output under **Final**, play the entire clip and check timing throughout. Check for missing speech, room voices, clipped dialogue, obvious processing artifacts, unsuitable skin color and incorrect rotation. Save a handoff note and mark the clip **Ready for human edit** only after review. Otherwise leave **Needs editor review** or **On hold**.

The human editor then handles shot selection, story cuts, captions, music, branding and final polish in their editing tool. For a new 4K deliverable, use the original footage, approved/corrected grade and clean WAV in that tool; the app's new preparation exports are not 4K masters.

## 7. Troubleshooting

| Problem | Next step |
|---|---|
| Python command not found | Install Python with pip and verify `py -3` or `python` before running setup. |
| Setup failed | Read the setup terminal error, check the internet connection and pip, then retry. |
| Browser does not open | Use the local URL printed in the launch terminal; keep that terminal running. |
| Actions say viewing-only mode | Launch Start_Windows.bat and use its local browser URL. |
| FFmpeg missing | Complete setup, or set a compatible FFmpeg executable in Settings. |
| Folder picker unavailable | Paste the source folder's full Windows path. |
| Import needs more disk space | Move the app folder to a larger writable location before importing. Do not move source footage to fix it. |
| Audio does not cover the trim | Narrow the camera in/out range to the recording's actual overlap or choose the correct recording. |
| No good match | Listen/manual-sync, obtain the right recording, or explicitly flag camera-audio fallback. |
| Browser cannot preview a codec | Save/open the file in the editing tool; H.264 1080p previews are more compatible. |
| Drive letter changed or disconnected | Reconnect/check the actual location before retrying. Never assume the original path still works. |

Wait for jobs to finish before closing the app or safely ejecting the drive. Do not expose the local server to the network.

## Developer acceptance checklist

Read [CODEX_HANDOFF.md](CODEX_HANDOFF.md) before changing the pipeline. Run the isolated regression tests after setup:

```bat
py -3 -m unittest -v test_app
```

Then test Windows folder selection, one real import, a checked audio candidate, saved settings, a grade preview and a full short render. Verify video/audio quality by watching and listening, not just by passing tests. Preserve source files, old exports, relative project paths and explicit fallback warnings. Do not add paid services, upload client media, invite collaborators, or begin bulk processing without the user's instruction.
